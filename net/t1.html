01选题背景

院系网站的真正痛点是"更新难"：一则通知要经过写稿、排版、上传、找管理员替换文件，平均两三天才能上线。本选题把"前台展示 + 后台发布"作为一套完整系统来设计，重点验证内容从录入到上线的全链路，而不是只画几个漂亮页面。

02设计思路

前后台共用一套设计语言，但操作密度完全不同：前台留白、少控件；后台紧凑、控件密集且状态明确。所有内容都有且只有一个状态（草稿 / 待审核 / 已发布），状态决定它在哪出现。

  • 登录页不堆信息，只保留身份与一行动机说明。
  • 列表页把"状态"放在最显眼的位置，颜色即语义。
  • 危险操作（下线）与常规操作（编辑）在视觉上分层。
  • 移动端后台把侧栏折成横向标签，保证单手可操作。

03「五心」主题体现

红心：栏目围绕"服务地方"设置校企合作与就业板块，让门户承担对外表达的功能。仁心：每条操作都有反馈（toast 提示），不让人担心"到底存没存上"。恒心：状态机改了五版，最终收敛为三态，多一个都不加。匠心：表格行高、按钮圆角、状态色全部对齐同一套度量。创心：用浏览器本地存储模拟数据库，答辩现场断网也能完整演示。

04技术实现

演示版以 localStorage 承担数据层，前端用原生 JS 做状态渲染；真实部署时替换为接口层即可，页面结构不必改动。

localStorage 数据层 状态机（三态） 事件委托 CSS Grid 后台布局 表单校验 无框架依赖

05可拓展方向

  • 接入真实登录（会话 / Token）与角色权限（编辑、审核、管理员）。
  • 增加图片上传与媒体库管理，支持封面裁剪。
  • 补充操作日志与版本回滚，满足学校内容留痕要求。
